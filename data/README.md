## Timestamp warning

The CSV stores timestamp text with microsecond precision but without `Z` or an offset. The supplied research brief states that the timestamps originated in UTC. That statement must be recorded as external provenance metadata. Preprocessing must:

1. retain the original timestamp string;
2. parse it as UTC only under the documented source assertion;
3. create a separate timezone-aware canonical timestamp;
4. record parse failures and any normalization; and
5. never silently convert the values to Asia/Jakarta time.

The intake scan found monotonically increasing timestamps. The median adjacent interval was about 3.53 seconds, while the maximum observed gap was about 1,747 seconds. Therefore, the data cannot be treated as an exact one-minute grid without an explicit and justified alignment policy.

## Raw data policy

Place the local file at `data/raw/sensor_data.csv` when running experiments. `data/raw/` is ignored by Git. Do not commit credentials, camera frames, identifiable imagery, or the full export.

## Planned generated files

- `data/sample_sensor_data.csv`: deterministic, non-sensitive sample produced by a script.
- `results/tables/dataset_summary.csv`: regenerated dataset profile.
- `results/tables/data_quality_summary.csv`: validation, duplicate, and gap counts.
- a preprocessing audit log with row counts and reasons for every transformation.

See [data_dictionary.csv](data_dictionary.csv) for raw-to-canonical mappings.

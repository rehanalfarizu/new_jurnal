## 1 What already exists

### Sensing and edge acquisition

- ESP32 firmware reads DHT11 environmental telemetry and legacy ZMPT101B/SCT013 electrical signals, calculates power, timestamps payloads, and publishes through Azure IoT Hub MQTT/TLS.
- The firmware also contains TinyML-style anomaly fields and an IR AC closed-loop path. Those are application features, not evidence of forecasting performance or safe autonomous control.
- One Raspberry Pi implementation uses YOLOv3-tiny and publishes `jumlahOrang` telemetry to Azure IoT Hub.
- A second Raspberry Pi implementation uses YOLOv8 and exposes a local count/stream service.
- A Raspberry Pi local API stores the latest ESP32, camera, and gateway-health values in memory.

### Cloud and historical telemetry

- Azure Functions ingest IoT Hub messages and write sensor and people-count entities to Azure Table Storage.
- Direct occupancy messages are stored in a separate `PeopleCount` table.
- The gateway path can write an aggregated `SensorTelemetry` entity that includes the latest `people_count` alongside environmental and electrical values.
- `GetTelemetryData` exposes latest, history, statistics, and people-count endpoints.

### Dashboard and Digital Twin presentation

- The Vue application includes telemetry cards, historical charts, alerts, energy views, people-count views, 3D house visualization, maps, authentication adapters, and recommendation review UI.
- Current frontend code uses Azure HTTP polling and optional deterministic demo replay. The top-level README still describes real-time MQTT as if it were the dashboard transport.

### Machine learning and decision support

- A newer `ml_models` layer provides timezone-aware request validation, a canonical flat telemetry adapter, deterministic feature construction for 31 one-minute points, a 30-minute persistence baseline, a transparent comfort heuristic, and advisory AC scenario ranking.
- Nine non-API Python unit tests passed in the audit environment. The API test module could not run because Flask was not installed in the audit runtime.
- Legacy training scripts predict same-row power with random train/test splitting and train AC recommendations against labels generated by internal rules. Their historical metrics are not valid evidence for true 30-minute forecasting, occupancy benefit, comfort outcomes, or energy savings.

## 3 What is missing

- A reproducible export manifest linking the CSV to an exact Azure table/query/export command.
- Independent timestamps for sensing, occupancy detection, gateway merge, cloud receipt, and storage update.
- A defensible temporal-alignment rule and occupancy staleness calculation.
- A nested canonical-state record with validation, quality flags, staleness, and source provenance per field.
- Traceable preprocessing with before/after row counts and no silent deletion.
- A true `power(t + 30 minutes)` target matched by time on irregular data.
- Chronological or rolling-origin partitions with a horizon purge at boundaries.
- Persistence, historical-power-only, environment-without-occupancy, and environment-with-occupancy comparisons under identical conditions.
- Reproducible MAE, RMSE, R-squared, uncertainty, residual, and subgroup analyses.
- A controlled occupancy ablation and robustness analysis.
- Digital Twin integrity metrics derived from explicit definitions.
- Decision-support scenario evaluation with recorded assumptions and no claim of observed savings or human outcomes.
- Programmatic result tables/figures and tests for leakage, timestamp handling, gaps, alignment, and metrics.

Physical-to-digital latency is not evaluable from the supplied CSV because it provides only one timestamp per row.

## Documentation discrepancies found

- The old top-level README names scripts and documentation paths that are absent at the inspected commit.
- It shows a build-passing badge without evidence from this audit.
- It describes dashboard MQTT delivery, while the current frontend implements Azure HTTP polling.
- It describes ML-based recommendations broadly, but the current deployed/function logic includes rule-based and heuristic paths.
- It presents a single architecture while the source contains multiple competing Raspberry Pi, ingestion, and recommendation paths.
- Existing audit documents describe `AdminDashboard.vue` as empty and the build as blocked; the current remote file is populated, so that finding is stale and requires a fresh build verification.
- The README displays an MIT badge, but no old-repository license file is tracked.
